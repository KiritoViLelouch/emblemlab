# Architecture decisions
Next.js App Router + TypeScript + Tailwind CSS 4 delivers six responsive Chinese-first pages. A small typed fetch client calls local FastAPI; no server-side invented result data. English names and aliases are retained in catalogs; UI text is centralized where shared, with a future locale dictionary migration available (no English UI in Phase 1).
FastAPI validates Pydantic v2 requests. The catalog repository loads and validates versioned JSON. FixtureRules implements the RuleEvaluator protocol; CP-SAT imports no HTTP code. The scoring layer owns configurable integer coefficients. Independent post-solve validation checks capacity, availability, locks, bans, equipment and slots before responses.
SQLAlchemy 2 uses a composite-key versioned entity store and same-game/same-ruleset foreign-key links. This deliberately avoids 15 speculative tables while preserving entity kinds, typed catalog payloads and provenance. SQLite migrations and imported snapshots work now; database-backed activation, statistics persistence adapters and full normalized relational models are Phase 2/3. PostgreSQL-compatible JSON/String columns; no PostgreSQL verification yet. Alembic initial revision freezes explicit table definitions for reproducible future upgrades. SQLite connections on the application engine enforce foreign keys.
Catalog fixture JSON is authoritative for this milestone. Manual import validates then archives Ruleset/Champion/Trait/Emblem records transactionally; export round-trips the ruleset. Future adapters must return the same schema, with permission/license checks, never private API calls. No runtime fetching.
Top-K solver uses one total time budget and conditional optimum per diversity exclusion. FastAPI sync routes execute in threadpool; no queue/microservices. UI stores at most two same-ruleset candidates locally. API has CORS only for configured local origins, no authentication; bind loopback for development.
Retained subsets are distinct from actual reforge actions. Locked indices refer to emblem instances, including duplicates; disallowed subsets are still listed. The legacy `actual_reforge` action remains rejected; Phase 4 adds a separate explicit scenario endpoint.

MVP verification fixes: request-dependent output clears when inputs change; configuration is disabled during requests. Compact API emblem indices explicitly map to original visual slots. Comparison checks emblem and holder identity. Catalog effects ignore obsolete responses. Network failures show a clear API connection message. Independent reference tests avoid production counting/scoring functions. Evidence and verification limits are in docs/MVP_REVIEW.md.

Phase 2 community import: standard-library CSV and read-only openpyxl parse bounded uploads; no external icon or source fetching. `app/importers/community.py` owns parsing, exact scoped label resolution, transactional persistence and corrections; `app/models/community.py` defines two separate community tables. Revision 0002 adds those tables without changing existing ones. Batches hold immutable game/version/source metadata and catalog/file digests; rows hold immutable raw cells, derived current mappings and append-only correction snapshots. Optimistic revision updates prevent lost edits. Changed catalog fingerprints block review until reimport. The additive guides router and `/guides` page expose upload/list/review independently of solver code and statistical observations. The metadata discriminator remains community recommendation even after human label review; no opinion is promoted to statistical evidence. Existing API outputs, fixture activation and scoring remain unchanged. Format, bounds and limitations: docs/COMMUNITY_IMPORT.md.

Phase 3 statistical ingestion: audited existing source stubs before implementation (STATISTICS_SOURCE_AUDIT.md). A provider protocol normalizes authorized exports; no network adapter ships. Operator-controlled, strictly validated source authorization is required separately from the HTTP bearer token. The additive statistics router streams bounded JSON into strict Pydantic schemas, then a worker thread validates full patch/catalog/context scope and commits immutable records transactionally. Dedicated statistics storage keeps opinions and match observations apart. Raw normalized inputs, source permission snapshot, content/catalog hashes and collection window are retained. Read paths recheck current permission and catalog fingerprints; revoked data is hidden. Explicit count derivations and conditional Wilson intervals live in a separate quality module; unknown metrics are never imputed. Queries keep providers/cohorts separate. No statistical reweighting or automatic solver enrichment was added, preserving existing optimizer/API results and avoiding joins between incompatible samples.

Phase 4: operator-controlled finite reforge laws are isolated from catalogs, community guidance and statistics. They bind the full game/patch/set/mode/ruleset scope and catalog digest. The analyzer exhausts original-instance subsets, fixed action orders and draw paths; exact rational probabilities are computed only under a declared verified law. Legal terminal multisets share one actual CP-SAT solve each with unchanged constraints and objective. Solver status gates complete ranges/EV, while unknown and infeasible values remain null. The additive API preserves legacy subset behavior. UI distinguishes pre-reforge baseline, legal actions, outcome compositions and risk. No migration or changes to optimizer scoring. Only synthetic laws ship. Contract, evidence assumptions and supported mechanics: REFORGE_ANALYSIS.md.


Phase 2A: authoritative JSON now includes `data/catalogs` (real normalized snapshots) plus explicit `data/fixtures`. A fixed manifest binds gameplay patch, resource build, set mutator, standard shop roster, reviewed emblem mapping and raw snapshot SHA-256 digests. The TFT importer is an offline adapter, independent of HTTP and CP-SAT; the optional downloader only uses pinned public source URLs. DataReadiness declares the verified profile, essential checks, excluded entities and unsupported mechanics. Shared validation gates real optimization. Native contribution weights and occupied board slots extend the existing evaluator/CP-SAT consistently; exclusive forms, trait count limits and incompatible trait pairs block unknown rules. No scoring formula, statistics pipeline or reforge EV feature was added. Existing synthetic reforge catalog fingerprints were regenerated solely because serialized catalog schemas gained additive fields. Existing archived community/statistical records retain stale-fingerprint protection and may require reimport.

The UI opts out of synthetic catalogs by default, handles empty JCC versions, and clears version-dependent emblem/unit constraints on switching. Metadata shows the restricted profile and source independently of optimizer results. Remote first-party art has a text fallback on network failure. A separate bounded manual CSV/XLSX adapter and read-only review API normalize JCC data into disabled drafts with file hashes/reviewer evidence. Uploads never become an active catalog and no TFT rules are copied into JCC. No migration was needed.

## 朋友公开测试部署（2026-10-10）

用户授权将现有 TFT 版本发布到 GitHub 网站。选择 GitHub Pages 静态导出 + 独立 Python 后端，不替换 CP-SAT、不将结果预计算成演示数据。公开模式用环境变量显式启用，服务端独立限制接口、目录、求解预算和并发；本地默认行为保留。部署文件和未执行的远程验收见 `DEPLOYMENT.md`。托管账户未就绪时不能宣称已上线。
